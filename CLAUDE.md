# Grille politique Présidentielle 2027

Lire `CAHIER_DES_CHARGES.md`. Le projet avance lot par lot : ne réaliser que le lot
demandé, puis s'arrêter pour faire vérifier le critère « Terminé quand ».

## Consigne permanente

Écrire un test par collecteur à partir d'une réponse enregistrée de la source
(`tests/reponses/`), pour repérer tout de suite un changement de format.

## Repères

- Python 3.11 ou plus ; dépendances dans `requirements.txt` ; tests : `python -m pytest`.
- Configuration modifiable sans code : `config/chaines.yaml` (une ligne par chaîne), `config/politique.yaml` et `config/evenements.yaml` (événements de dernière minute ajoutés à la main, `grille/evenements.py` ; identifiants « evenement:… » jamais annulés par les autres sources).
- Base SQLite `data/grille.sqlite` (ignorée par Git), table `emissions` (`invites` : personnes présentes, `cites` : seulement citées, `resume` : résumé de la source), `chaines_resolues` (identifiants YouTube), `collectes` (comptes rendus), `envois` (emails envoyés), `logos`, `annonces` et `douteux` (`grille/db.py`). Heures en ISO 8601, fuseau Europe/Paris.
- Collecteurs : `grille/tv.py` (lot 2), `grille/youtube.py` (directs et premières ; épisodes de séries publiés en vidéos ordinaires via `episodes:` dans chaines.yaml, colonne `nature` = « episode ») et `grille/twitch.py` (lot 3), `grille/radio.py` (API Radio France, après le lot 5 ; matinale longue retenue pour une personne dont le résumé donne l'heure de passage : remplacée par ce passage, `passages_annonces`), `grille/radios_privees.py` (grilles RTL, Europe 1, Sud Radio, RMC, Radio Classique : lignes radio à adresse web, un lecteur par site), `grille/agendas.py` et `grille/annonces.py` (lot 6), `grille/directs.py` (sujet du jour de l'émission en cours sur les pages du direct de france.tv, publié seulement au début de l'émission), `grille/invites_web.py` (invité encore inconnu au début d'une émission, cherché sur le web par Claude ; réglages `config/recherche.yaml` ; table `recherches_invites`, résultat dans `annonces` avec un identifiant « web:… », nom retenu s'il est dans politique.yaml ou, avec `accepter_fonctions`, si Claude lui donne une fonction politique (colonne `fonctions`, affichée comme un sigle) ; grandes émissions `a_surveiller:` (20 h de TF1 et France 2) ajoutées avec l'identifiant « recherche:… » seulement si un invité politique est trouvé ; comparaison des modèles : `python -m grille comparer-modeles`, `docs/essais_recherche.yaml`, `.github/workflows/essai-modeles.yml`). `grille/rss.py` (mesure des flux RSS de `config/rss.yaml` : annonces probables de passages médias, table `rss_annonces`, comptées dans l'email, jamais ajoutées à la grille ; candidatures de personnes absentes de politique.yaml, table `rss_candidats`, proposées dans l'email à partir de deux articles en 7 jours). Filtre politique commun : `grille/filtre.py` (liste blanche `creneaux:` : émission reconnue à son créneau horaire sur une chaîne, titre précédé de son nom, par exemple « À l'air libre » de Mediapart ; YouTube et Twitch). Bouton « Présidentielle 2027 » de la page : `grille/campagne.py` (rubrique `presidentielle:` et `campagne: true` de politique.yaml).
- Lot 6 : agendas des partis (`grille/agendas.py`, lignes `web` de chaines.yaml, un lecteur par site). Appliqué à l'affichage (`grille/affichage.py` : page, email, `lister`), jamais en base : invités annoncés par les communiqués de France Télévisions (`grille/annonces.py`, table `annonces`), passages médias des agendas rattachés à leur émission, puis dédoublonnage (`grille/fusion.py`). Cas douteux (`FiltrePolitique.noter_douteux`, table `douteux`) : mesurés dans l'email avant de décider du classement par Claude, jamais ajoutés à la grille.
- Page web (lot 4) : `grille/page.py` intègre les données dans `grille/modele_page/index.html` ; sortie dans `site/` (ignoré par Git). Aperçu : `python -m grille apercu`. Favoris : `grille/modele_page/favoris.js` (règles communes, gardées sur le téléphone). Lancement (`sw.js`) : la page gardée sur le téléphone s'affiche tout de suite (et se remet à jour en arrière-plan pour le lancement suivant), `app.js` (`rafraichir`) redemande aussitôt la grille du jour, `grille.json` (format décrit dans `docs/GRILLE_JSON.md`, `page.FORMAT_GRILLE`) ; fichiers appelés avec leur version (`?v=`, `page.VERSIONNES`) servis sans réseau.
- En ligne (lot 5) : `.github/workflows/collecte.yml` (collecte complète chaque heure à :45, collecte rapide `collecter-rapide` à :00, :15 et :30 — directs de france.tv, Radio France (journée en cours, 6 h – 23 h) et Twitch —, déclenchées par cron-job.org ; publie la page sur GitHub Pages et, si la variable `SCW_BUCKET` existe, sur Scaleway Object Storage avec `.github/scripts/scaleway.sh`) et `courriel.yml` (7 h, Paris). Base sur la branche `donnees` (`.github/scripts/base.sh`), jamais dans `main`.
- Notifications : `notifications/` (Cloudflare Worker, JavaScript, tests `node --test notifications/test/*.test.mjs`), publié par `.github/workflows/notifications.yml` ; relit `site/notifications.json` (écrit par `grille/page.py`) ; adresse dans `config/notifications.yaml`. Favoris et abonnements dans son espace KV, jamais dans le dépôt. Mesure d'audience anonyme (`notifications/src/mesures.js`) : la page compte ses interactions (`mesurer` dans `app.js`) et envoie ses totaux en fin de visite (POST `/mesure`) ; totaux par jour gardés 90 jours, sans identifiant ni heure ; jamais montrés par le service : seul l'email du matin les lit, directement dans le stockage Cloudflare (`courriel.lire_audience`, section « Utilisation de la grille hier »).
- Application iPhone et Android : `application/` (Capacitor 8, `capacitor.config.json` : affiche la page publiée, page locale `www/hors-connexion.html` sans réseau ; projets `android/` et `ios/` générés par `npx cap add`, Swift Package Manager côté iPhone) ; construction Android d'essai : `.github/workflows/application-android.yml` ; iPhone construit sur le Mac du propriétaire (Xcode).
- Secrets en local : fichier `.env` (modèle `.env.exemple`), ignoré par Git.
- Secrets uniquement en variables d'environnement : `RADIOFRANCE_API_KEY` (passe dans l'adresse : toujours la masquer dans les messages), `YOUTUBE_API_KEY`, `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`, `SMTP_SERVEUR`, `SMTP_UTILISATEUR`, `SMTP_MOT_DE_PASSE`, `EMAIL_DESTINATAIRE`, `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `ANTHROPIC_API_KEY` (recherche de l'invité par Claude), `SCW_ACCESS_KEY`, `SCW_SECRET_KEY` (publication sur Scaleway ; nom du stockage dans la variable GitHub `SCW_BUCKET`). Le dépôt est public : aucune adresse email ni clé dans les fichiers.
- Points d'accès et quotas confirmés : `docs/VERIFICATIONS.md`.
- Code, messages et commentaires en français.
